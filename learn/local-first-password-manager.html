What does "local-first" actually cost?

Three things, and they are not small: you handle multi-device sync, you own the backups, and a lost laptop is a lost vault unless you prepared for it. The benefit is real — nobody else holds your key — but a comparison that only lists the benefit is an advertisement.

Updated 2026-11-17 · by cygnus, the developer of Bitcoffer

The definition, reduced to two questions

"Local-first" gets used loosely enough to mean almost anything. Two questions cut through it:

  1. Where does the ciphertext live? On your disk, or on a server that could be compelled, breached, or shut down.
  2. Who can derive the key? Only you, from something you know and hold — or also the vendor, because recovery goes through their account system.

A service where you hold the key and they hold an encrypted blob is meaningfully different from one where they hold both. But it is not the same as holding everything yourself, and the difference is precisely where the costs appear.

Cost 1: multi-device sync becomes a procedure

With a cloud manager, a second machine is a login. With a local vault, a second machine is a file transfer, and you have to decide how it happens:

ApproachWhat it costsWhere it breaks
Encrypted backup to a USB drive, restored on the other MacManual, and you must remember to do itYou forget for six weeks and the second Mac holds stale passwords
Vault file in iCloud Drive or DropboxConvenient, and it re-introduces a cloud provider into the storyTwo machines writing one file produce conflicts; the provider now holds your ciphertext even though it cannot read it
Export and import via 1PUX or CSVFully manual, and plaintext leaves the vault during exportPlaintext export is the most dangerous artifact in this workflow — delete it every time

None of these is wrong. What is wrong is choosing a local-first manager without noticing that this decision is now yours. A sync conflict on a password vault is not a merge conflict on a text file: you cannot look at both versions and pick the better one, because you cannot read either.

Cost 2: backups are yours, and a backup you have not restored is a hypothesis

The reason cloud managers charge money is partly that they run backups you never think about. Removing the backend removes that. What a local vault owes you in exchange is a recovery path you can test:

  • An encrypted backup you can restore. Not "an export exists" — a restore you have performed once with data you did not care about.
  • A recovery code kept somewhere that is not the machine. Bitcoffer wraps the vault's data key with a recovery key derived from a code you store yourself, using AES-256-GCM. Lose both the master password and the code and the vault is gone, by design — there is no support line that can unlock it, because there is no key escrow.
  • A deletion path that forces the first two. A "delete vault" action that does not stop to ask for a backup is a data-loss bug with a friendly name.

This is the cost that most often gets discovered the hard way. The design question to ask any vendor is not "do you support backups" but "what exactly happens to my data if I forget my master password and lose the recovery code" — and the honest answer for a real local-first product is "it is unrecoverable".

Cost 3: a lost device is a lost vault until you prove otherwise

Laptop stolen, disk dead, macOS reinstalled without a migration: in each case the vault came with the machine and left with it. The difference between an inconvenience and a catastrophe is one artifact — a backup, or a second device holding the same data — and whether you checked it this quarter.

A practical rule: if you cannot name the last time you restored your vault, you do not have a backup. You have a file you believe in.

What you get for those three costs

  • No server to breach. There is no table of encrypted blobs with your email attached, because there is no server. A breach that does not exist cannot leak you.
  • No account to be locked out of. Nothing to suspend, nothing to require a phone number for, no policy change that ends your access.
  • A vendor that cannot be compelled to hand over what it does not have. This matters more for some people than others, and it is a legitimate reason to accept the three costs above.
  • The claim is checkable. A backend you cannot see is a promise; a vault file on your disk and a closed network entitlement are facts you can inspect. The four checks take five minutes.

When a cloud manager is the better answer

Be honest about this list, because choosing against it deliberately is different from being sold against it:

  • You use more than two devices, or switch often. A family with four machines and two phones will have a worse time with manual sync than with a subscription.
  • You share credentials with other people. Shared vaults need a server, or a lot of discipline. Local-first means one person, one file.
  • You will not test a restore. If the backup discipline is not going to happen, letting a provider run it is the safer choice — as long as you understand the trade you just made.
  • You need browser autofill everywhere. A desktop vault and a browser extension solve different problems; pick the one that matches where you actually type passwords.
